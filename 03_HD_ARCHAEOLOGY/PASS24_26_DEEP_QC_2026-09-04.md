## Scope
This QC audits Passes 24, 25 and 26 against their local artifacts, the reference replay corpus, and current parser/model source.

## Pass 24 — strengths
1. The lifecycle census is internally consistent: 1,493 DE_QUEUE + 471 BUILD + 118 RESEARCH + 33 DELETE = 2,115 candidates.
2. Actor-ID reuse is correctly treated as continuity rather than completion evidence.
3. Research-object reuse is a strong counterexample to naive object-identity closure.
4. The falsifier requirement is appropriate: promotion needs accepted/pending state, stable realized identity, authoritative completed-tech state, or independently validated lifecycle state.

## Pass 24 — QC findings
**P24-C1 / HIGH:** The artifact does not preserve the exact executable query/code used to obtain the 1,487/1,493, 418/471 and temporal-correlation counts. These numbers are plausible and previously observed, but the audit is not independently reproducible from the artifact alone.

**P24-C2 / MEDIUM:** “Later ACTION reusing at least one supplied actor ID” is a deliberately weak linkage predicate. It should be labeled `ACTOR_CONTINUITY`, never `IDENTITY_MATCH`, because a producer/builder can issue many unrelated commands.

**P24-C3 / MEDIUM:** The +5,000 sequence window is a screening heuristic, not a temporal semantics proof. The artifact correctly avoids promotion, but the window should be explicitly labeled arbitrary/screening-only and not treated as a lifecycle interval.

**P24-C4 / LOW:** W1 is discussed alongside W2, but the experiment mainly attacks realization. W1 requires authoritative accepted/pending state; the absence of that channel should be stated independently from W2.

## Pass 25 — strengths
1. Correctly distinguishes aggregate counters from per-object state.
2. Correctly retains SYNC deltas as derived/context evidence rather than lifecycle truth.
3. Correctly tests all four candidate lifecycle classes rather than only production.
4. Negative tests prevent the common “count increased therefore object completed” error.

## Pass 25 — QC findings
**P25-C1 / HIGH:** The claim that deltas are “highly heterogeneous” is asserted without reporting the actual per-class distributions/ranges in the artifact. A future audit should publish min/max, zero rate, median and frequency table for each lifecycle class.

**P25-C2 / HIGH:** “Nearest preceding and following populated SYNC records” is underspecified. The artifact should record whether matching is by replay sequence, record order, or timestamp, and whether equal-time records are possible.

**P25-C3 / MEDIUM:** The parser source calls the DE per-player values guesses, but that does not make the byte fields meaningless. Field 6 has an explicit maintainer hypothesis. The correct conclusion is `semantic interpretation unproven`, not `field has no lifecycle information`.

**P25-C4 / MEDIUM:** “Two player states” is a property of the normalized reference output, not necessarily a statement about the original SYNC block. Keep this distinction explicit.

## Pass 26 — strengths
1. Correctly identifies genuine initial object identity in the richer model: class/object/instance/index/position.
2. Correctly observes that the model's body timeseries retains aggregate resources/object counts.
3. Correctly separates semantic enrichment from completion semantics.
4. Correctly refuses W2 closure merely because an action has a known unit/building/technology definition.

## Pass 26 — QC findings
**P26-C1 / CRITICAL:** The artifact is partly source archaeology, not a demonstrated parse of the user's reference replay through the richer model. Therefore statements about what the richer model does to the reference corpus must be labeled `SOURCE-DIRECT`, unless the exact local package was executed against the corpus.

**P26-C2 / HIGH:** The phrase “does not supply a proved ... ledger” is stronger than necessary unless the full relevant source surface was exhaustively audited. Safer: “the audited model path does not expose such a ledger.”

**P26-C3 / HIGH:** Version provenance is missing. Current upstream `aoc-mgz` is a moving target and AoE2 replay formats change across patches. The exact commit/version audited must be recorded before using source findings as implementation requirements.

**P26-C4 / MEDIUM:** `Inputs` cache reuse must not be characterized as “input normalization” without citing its exact implementation path. The conclusion is likely correct, but the artifact needs an exact source anchor.

## Cross-pass architectural QC
The three passes form a valid escalation:
`command candidate → actor/temporal correlation → aggregate SYNC → richer static/model identity`.
They correctly converge on the same boundary: command evidence is strong, but lifecycle realization remains unproven.

The main weakness is not analytical direction. It is **audit reproducibility and provenance granularity**. Passes 24–26 should not be used as a basis for confidence scores beyond W0 until their exact scripts, source versions and measurement definitions are archived.
