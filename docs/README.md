# AEGIS Knowledge Repository

This repository is the long-term engineering memory for the AEGIS Byzantine AI project. It is not merely a source tree. It preserves the reproducible body of knowledge required to continue the project after any individual development session.

## Repository doctrine

Knowledge is evidence-indexed. Canonical implementation, experiments, archaeological evidence, machine evidence, and historical material are kept distinct. Claims are never promoted from hypothesis to fact without evidence.

## Layer model

- **Layer 1 — Machine:** operational contract for AoE2DE's AI execution environment, script semantics, scheduling, state/action substrate, native interfaces, loader boundaries, XS, and error/recovery behavior.
- **Layer 2 — Strategy:** competitive causality, strategic state, beliefs, objectives, capability, economy, production, timing, initiative, transitions, resource taxation, and failure recovery.
- **Layer 3 — Byzantine Doctrine:** civilization-specific strategic specialization after general strategy has been reconstructed.
- **Layer 4 — Implementation:** validated architecture and runtime candidate built against the machine contract.

## Knowledge classes

FACT; MECHANICAL_FACT; HEURISTIC; STRATEGIC_PRINCIPLE; TACTICAL_PRINCIPLE; TRANSITION_PRINCIPLE; ECONOMIC_PRINCIPLE; FAILURE_HEURISTIC; ENGINE_WORKAROUND; HISTORICAL_ARTIFACT; BUG_COMPENSATION; HYPOTHESIS; LESSON.

## Evidence discipline

Each substantive claim should identify its source, evidence strength, status, known counterexamples, engine constraints, and implementation implications where applicable. Source-derived observations, model inference, and outside research must remain distinguishable.

## Current authority

PORPHYRA V2.2.2 is the immutable control baseline. V3 is the designated strategy source/fossil. HD source is the principal strategic-knowledge archaeological specimen. Experimental OMEGA/ADPromisory material is evidence, not automatic runtime authority. Proprietary AoE2 binaries and stock source remain local unless separately authorized for publication.

## Continuation rule

A future engineer should be able to reconstruct what was learned, why it was believed, what remains uncertain, which evidence supports it, and where implementation should proceed without relying on conversational memory.
