# Security and Provenance Policy

## Principle

The repository is the project's long-term memory, but not every artifact that exists locally is suitable for publication.

## Allowed preservation

Preserve project-owned source, generated analyses, manifests, hashes, methodology, derived knowledge, experimental results, replay analysis, and documentation when licensing and authorization permit.

## Restricted material

Do not publish proprietary AoE2 binaries, stock AI source, credentials, private account information, or other restricted material merely because it is useful to the project. Keep restricted artifacts local and preserve non-sensitive hashes, manifests, or derived findings where appropriate.

## Provenance

Every preserved derived artifact should identify its source and, where practical, source hash/build/version. If a result depends on a local proprietary artifact, the repository should describe the dependency without embedding the restricted artifact.

## Evidence integrity

Never rewrite historical evidence to make an experiment appear successful. Corrections should be additive or explicitly marked. Superseded claims remain discoverable with their reason for supersession.

## Publication review

Before adding a new external or native artifact, classify ownership/licensing and sensitivity. If uncertain, preserve a derived description or local-only reference rather than copying the underlying restricted material.
