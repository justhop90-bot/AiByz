## State categories

### Strategic state
Represents intent and priorities. It must not be confused with physical engine state.

### Demand state
Represents a requirement generated by strategy or operating services.

### Reservation state
Protects scarce resources while a demand is being fulfilled. Engine escrow and AEGIS bookkeeping must remain distinguishable.

### Execution state
Represents an issued physical operation and its endpoint/order/object relationship.

### Observation state
Represents what the engine/replay-visible substrate confirms actually exists.

### Verification state
Determines whether an issued operation produced the expected observable transition.

### Recovery state
Classifies failure and determines whether to retry, replace, defer, or abandon.

## Critical lifecycle separation

The reconstruction must preserve this sequence where the historical system supports it:

```text
REQUESTED
  → ADMITTED
  → RESERVED
  → ENDPOINT_SELECTED
  → AUTHORIZED
  → COMMAND_ISSUED
  → ENGINE_OBSERVED
  → CONFIRMED
```

A source rule that performs the command is not automatically evidence that all later states occur in the same rule or same interpreter pass.

## Coupling hotspots

The highest-risk static coupling areas are:

1. goals shared by strategy and operating services;
2. strategic numbers used simultaneously as policy and control state;
3. construction placement state consumed by builder assignment;
4. worker task state consumed by economic reconciliation;
5. threat state feeding construction/economy/retreat;
6. pending objects bridging command issuance and observation;
7. escrow state gating multiple competing production classes;
8. position/search state shared by scouting and tactical systems.

## Reconstruction criterion

A subsystem is not structurally reconstructed until its major state channels have:

- producers identified;
- consumers identified;
- resetters identified;
- activation conditions identified;
- engine-facing effects identified;
- failure/recovery relationships identified;
- unresolved temporal semantics explicitly marked.

This is the minimum information required before AEGIS ownership can safely be assigned.

## No-runtime rule

This artifact is intentionally static. It does not authorize runtime experiments. Runtime qualification begins only after the corresponding state-flow hypothesis has been completely specified and the experiment has a narrowly defined falsifiable question.
